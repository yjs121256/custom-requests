How to Audit a CSV File Before Import: Duplicates, Missing Fields and Data Errors

A CSV import looks simple: export from one system, upload to another. Then the trouble starts. The new store shows the same product twice. Half the customer records have no email. Dates import as text, phone numbers lose their leading zero, and an accented name turns into strange symbols.

Most of these problems are visible in the file before you import it, if you know where to look. Here is a practical audit checklist you can run in Google Sheets or Excel.

Step 0: Never edit the original

Make a copy of the file and work on the copy. Keep the original export untouched so you can always go back and compare. If the file contains personal data, limit who can open it.

Step 1: Open it the right way

Double-clicking a CSV in Excel can silently change your data: long numbers become scientific notation, leading zeros disappear and some text turns into dates. Instead, import it (in Excel, Data → From Text/CSV; in Google Sheets, File → Import) and set sensitive columns like IDs, ZIP codes and phone numbers to text.

Also check the encoding. If you see characters like "Ã©" where "é" should be, the file is probably UTF-8 being read as something else. Re-import with UTF-8 selected.

Step 2: Check the structure

Before looking at values, confirm the shape of the file:

  • Do the column headers match what the destination system expects, spelled exactly?
  • Does every row have the same number of columns? A stray comma inside an unquoted field shifts everything to the right.
  • Are there blank rows or summary rows (like "Total") at the bottom that shouldn't be imported?

Step 3: Find duplicates

Decide first what "duplicate" means for this file. For customers, it might be the same email. For products, the same SKU. For orders, the same order number.

  • Use =COUNTIF(A:A, A2)>1 in a helper column to flag repeated keys.
  • Clean keys before comparing: =LOWER(TRIM(A2)) catches "Anna@Example.com " versus "anna@example.com".
  • Look for near-duplicates too, such as the same customer with two spellings of their name but the same phone number.

Don't delete duplicates automatically. Flag them, review them, then decide which record to keep.

Step 4: Find missing fields

List the columns the destination system requires, then count blanks in each:

  • =COUNTBLANK(B2:B) per required column gives a quick overview.
  • Filter each required column for blanks to see the rows affected.
  • Watch for "fake" values that aren't blank but are just as empty: "N/A", "-", "0" or "test".

Step 5: Check formats and values

This is where most import errors come from:

  • Dates: are they all in one format? Mixed 03/04/2026 and 2026-04-03 means some may be read with day and month swapped.
  • Numbers: prices with currency symbols or commas as decimal separators may import as text.
  • Emails: a simple check for "@" and a dot after it catches obvious typos.
  • Phone numbers: consistent format, country code if needed, no lost leading zeros.
  • Allowed values: columns like status, country or size should only contain values from a fixed list.
  • Lengths: some systems cut off long text fields or reject them.

Step 6: Write down what you found

An audit is only useful if someone can act on it. For each issue, record the row, the column, what's wrong and the suggested fix. A short summary at the top (how many rows, how many duplicates, how many missing required fields) helps you decide whether the file is ready or needs to go back to whoever exported it.

Step 7: Test with a small batch

Even after a clean audit, import 5–10 rows first and check them in the destination system before importing everything. It's far easier to fix ten records than ten thousand.

A quick audit checklist

  • [ ] Working on a copy
  • [ ] Imported with correct encoding and text columns
  • [ ] Headers match the destination exactly
  • [ ] Same column count on every row
  • [ ] Duplicates flagged by key
  • [ ] Required fields checked for blanks and fake values
  • [ ] Dates, numbers, emails and phones in consistent formats
  • [ ] Issues logged with row and column
  • [ ] Small test import done

FAQ

Can I do this in Google Sheets, or do I need special software? Google Sheets or Excel is enough for most files. Very large files may be slow to open in a spreadsheet.

Should I remove duplicates before importing? Flag and review them first. Two rows with the same email may hold different, useful information that should be merged rather than deleted.

Why do my leading zeros disappear? The spreadsheet treated the column as a number. Import the CSV and set that column to text.

What's the most common import error? Header names that don't match what the destination expects, followed by missing required fields and inconsistent date formats.

Does an audit change my data? An audit identifies and reports problems. You get an issue report with next steps; the Standard tier adds a checklist and one re-check after you've made fixes.
